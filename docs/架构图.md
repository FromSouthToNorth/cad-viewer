# 项目流程图与架构图

> 本文档描述本工作区(`cad-viewer` + `realdwg-web` 联合开发)的整体架构与关键流程,
> 图表基于当前代码实现绘制(2026-08)。性能优化背景与改动细节见
> [性能优化总结.md](./性能优化总结.md)。

---

## 1. 工作区总体架构

```mermaid
flowchart TB
    subgraph WS["cad 工作区"]
        CV["cad-viewer<br/>查看器 monorepo<br/>(Vue 组件 / 简单查看器 / CLI / 插件)"]
        RW["realdwg-web<br/>解析核心 monorepo<br/>(data-model / geometry-engine / graphic-interface)"]
        DATA["data/<br/>真实矿图 DXF 测试数据<br/>(95MB·38 万实体等)"]
        DOCS["docs/<br/>性能优化总结 · 架构图"]
    end

    LINK["use-local-realdwg.mjs<br/>修改 pnpm-workspace.yaml overrides<br/>@mlightcad/* → file:../realdwg-web/packages/*"]
    BENCH["realdwg-web/tools/bench/<br/>夹具生成 · 解析基准 · 坐标扫描 · 调试脚本"]

    CV -->|"pnpm overrides(开发期本地联动)"| LINK
    LINK --> RW
    RW -.->|"@mlightcad/* 包产物"| CV
    DATA -.->|"性能测试输入"| RW
    DATA -.->|"打开验证"| CV
    BENCH --> RW
    DOCS -.->|"记录改动与数据"| WS
```

- **cad-viewer**:纯浏览器 DWG/DXF 查看器与编辑器,依赖 `@mlightcad/*` 包做解析。
- **realdwg-web**:解析核心,仿 AutoCAD ObjectARX API,输出 `data-model` 等 npm 包。
- 开发期通过 `use-local-realdwg.mjs` 把 cad-viewer 的依赖指向本地 realdwg-web
  构建产物,实现两库联动调试;**发布前必须 `--off` 还原**。

## 2. 文件解析总体流程(DXF / DWG)

```mermaid
flowchart TB
    APP["应用代码<br/>file.arrayBuffer() → new AcDbDatabase()"]
    AC["acdbHostApplicationServices().workingDatabase = db<br/>(解析前必须设置工作数据库)"]
    READ["db.read(buffer, options, AcDbFileType)"]
    MGR["AcDbDatabaseConverterManager.instance.get(fileType)"]
    DXF{"文件类型?"}
    NATIVE["AcDbNativeDxfConverter<br/>内置 MIT 解析器,Worker 词法解析 + 主线程语义构建<br/>(默认注册;Worker 不可用时回退主线程)"]
    DWG["AcDbLibreDwgConverter<br/>LibreDWG 解析器,Web Worker + WASM<br/>(需手动注册,GPL 隔离)"]
    DB["AcDbDatabase<br/>符号表(Layer/Linetype/TextStyle/BlockTable…)<br/>+ BlockTableRecord 中的实体"]
    EVT["events.entityAppended 分块派发<br/>(endEventBatchChunked)"]

    APP --> AC --> READ --> MGR --> DXF
    DXF -->|"DXF"| NATIVE
    DXF -->|"DWG"| DWG
    NATIVE --> DB --> EVT
    DWG --> DB
```

**要点**

- DXF 转换器默认注册,DWG 转换器需先
  `AcDbDatabaseConverterManager.instance.register(AcDbFileType.DWG, ...)`。
- 解析完成后实体存放于 `AcDbBlockTableRecord`(模型空间/图纸空间),
  并通过 `entityAppended` 事件分块通知查看器,是渐进式渲染的数据入口。

## 3. DXF 解析管线(Worker 词法解析 + 主线程语义构建)

```mermaid
flowchart LR
    BUF["ArrayBuffer<br/>(含 GBK/ANSI_936 编码文本)"]
    WOK["dxf-parser-worker.js(Web Worker)<br/>编码解码 + AcDbDxfPairReader 词法扫描<br/>零分配热路径(acdbReadDxfCodeFromChars 等)"]
    WIRE["AcDbDxfPairWireData(SoA 线格式)<br/>codes/types/numbers typed arrays 零拷贝 transfer<br/>+ 去重字符串表"]
    ARR["acdbMakeDxfPairArrayReader<br/>主线程回放 pair 流(同一 AcDbDxfPairReader 接口)"]
    FIL["AcDbDxfFiler<br/>流式读取 DXF 组码对(readItem / peekItem)"]
    DOC["AcDbDxfDocumentReader<br/>按 SECTION 分派"]
    HEAD["HEADER 段<br/>acdbDxfInHeader<br/>系统变量 · HANDSEED"]
    TAB["TABLES 段<br/>符号表:LAYER/LTYPE/STYLE/VPORT/UCS/DIMSTYLE…"]
    BLK["BLOCKS 段<br/>块定义(含 INSERT 引用)"]
    ENT["ENTITIES 段<br/>AcDbDxfEntityFactory<br/>→ AcDbLine/AcDbPolyline/AcDbSpline…"]
    OBJ["OBJECTS 段<br/>字典 / GROUP / 其他对象"]
    BTR["BlockTableRecord(模型/图纸空间)"]
    PROG["进度上报 START→PARSE→ENTITY→END<br/>+ 时间预算让出(yieldGate)"]

    BUF --> WOK --> WIRE --> ARR --> FIL --> DOC
    DOC --> HEAD --> TAB --> BLK --> ENT --> OBJ
    ENT --> BTR
    BLK --> BTR
    BTR -->|"endEventBatchChunked 分块 flush"| PROG
```

**要点**

- `AcDbNativeDxfConverter.read()` 分 `START → PARSE → ENTITY → END` 四个阶段,
  每阶段带百分比进度;ENTITY 段按块 flush,并在单帧时间预算内主动让出主线程。
- 词法解析(字节 → 组码对)默认在 Web Worker 中完成,pair 流以 SoA typed-array
  线格式零拷贝回传;语义构建(表/实体/属性链接)在主线程走与原先完全相同的
  filer/document-reader 管线。Worker 不可用(Node、bundle 缺失、任务失败)时
  自动回退主线程流式解析,行为一致。
- HANDSEED 超过 `Number.MAX_SAFE_INTEGER` 时 `AcDbDatabase` 自动切换 BigInt 计数,
  避免 `generateUniqueHandle` 死循环(16% 卡死修复)。

## 4. DWG 解析管线(Web Worker + WASM 隔离)

```mermaid
sequenceDiagram
    autonumber
    participant APP as 应用主线程
    participant CONV as AcDbLibreDwgConverter
    participant WKR as AcDbLibreDwgParserWorker(独立 worker 包)
    participant WASM as libredwg-web.wasm(LibreDWG)
    participant DB as AcDbDatabase

    APP->>CONV: db.read(buffer, options, AcDbFileType.DWG)
    CONV->>WKR: postMessage(文件字节, useWorker: true)
    WKR->>WASM: 调用 LibreDWG 解析
    WASM-->>WKR: 原生解析结果
    WKR-->>CONV: postMessage(解析后的 JSON 模型)
    CONV->>CONV: AcDbEntitiyConverter / AcDbObjectConverter<br/>JSON → AcDbEntity
    CONV->>DB: 实体写入符号表与 BlockTableRecord
    DB-->>APP: entityAppended 分块事件
```

**要点**

- GPL 的 LibreDWG 解析器只存在于独立的
  `libredwg-parser-worker.js` + `libredwg-web.wasm` 资产中,运行时加载,
  与 MIT 核心通过 `postMessage` 通信,避免 GPL 代码混入主应用包。
- worker 脚本与 wasm 需从 `@mlightcad/libredwg-converter` 的 `dist/`
  部署到同一静态目录。

## 5. 查看器打开文件与渐进式渲染流程

```mermaid
sequenceDiagram
    autonumber
    participant USER as 用户
    participant DM as AcApDocManager
    participant DOC as AcApDocument(工作数据库)
    participant DB as AcDbDatabase(解析核心)
    participant VW as AcTrView2d(视图)
    participant RND as AcTrRenderer(three.js)
    participant PG as AcApOpenFileProgressController(进度 UI)

    USER->>DM: openDocument(File)
    DM->>DOC: 创建文档,设置 workingDatabase
    DM->>PG: 开始打开进度(百分比 + 进度条)
    DM->>DB: db.read(buffer, options, fileType)
    DB-->>PG: START / PARSE / ENTITY 阶段进度
    loop 实体分块 flush
        DB-->>VW: entityAppended(每块若干实体)
        VW->>VW: 入队 → drain 循环 batchConvert(渐进式)
        VW->>VW: 单帧时间预算内让出(防 rAF 饥饿)
        VW->>RND: 中段 WebGL 绘制(画面可交互)
        RND-->>PG: 场景排空进度回显
    end
    DB-->>PG: END(100%)
    VW->>VW: 最终 zoom-to-fit(AcTrProgressiveOpenFitController)
    VW->>RND: rAF 渲染循环(平移 / 缩放 / 拾取)
```

**要点**

- `progressiveRendering = true`(默认)时实体转换与绘制交叠进行,
  打开大图期间浏览器实测最大帧间隔约 91ms;关闭则一次性建图,帧循环饥饿 12s+。
- 无头导出(`cad-simple-viewer-cli`)显式传 `progressiveRendering: false`,
  不做无意义的让出。

## 6. 实体渲染管线(实体 → 批次 → GPU)

```mermaid
flowchart TB
    ENT["AcDbEntity(线/圆/弧/多段线/文字/图块引用…)"]
    WD["worldDraw(AcGi 绘制接口)"]
    GI["AcGiRenderer → 图元(线/网格/点/文字)"]
    POL["批次策略 AcTrBatchDrawPolicy<br/>按图层/样式/类型聚合<br/>RTE_REBASE_THRESHOLD(1e6) 判断是否合批"]
    BAT["合批对象<br/>AcTrBatchedLine / AcTrBatchedLine2 /<br/>AcTrBatchedMesh / AcTrBatchedPoint<br/>(顶点按批原点 rebase)"]
    UNB["unbatch 路径(超阈值实体独立绘制对象)"]
    SC["AcTrScene(场景图)<br/>AcTrLayer / AcTrLayout / 可见性控制"]
    GL["AcTrRenderer + AcTrViewportView / AcTrCamera<br/>three.js WebGLRenderer → Canvas"]
    MT["文字/MTEXT:AcTrMTextRenderer<br/>可选独立 worker 排版"]

    ENT --> WD --> GI --> POL
    POL -->|"常规实体"| BAT --> SC
    POL -->|"大坐标实体"| UNB --> SC
    SC --> GL
    GI -.->|"文字图元"| MT --> SC
```

**要点**

- 大坐标矿图(全部实体 |坐标| ≥ 1e6)会 100% 走 unbatch 路径,失去合批收益;
  且渲染管线无全局原点平移,float32 精度崩坏导致缩放时图层丢失——
  这是 M3+ 阶段的首位遗留工作,详见
  [性能优化总结.md 第 6 节](./性能优化总结.md)。

## 7. 核心类结构(ObjectARX 风格)

```mermaid
classDiagram
    class AcDbObject {
        +objectId / handle
    }
    class AcDbSymbolTable {
        +iterator / getAt / has
    }
    class AcDbSymbolTableRecord
    class AcDbBlockTableRecord {
        +appendAcDbEntity(entity)
    }
    class AcDbEntity {
        +layerId / color / linetype
        +worldDraw(AcGiContext)
    }
    class AcDbCurve {
        +startPoint / endPoint / length
    }
    class AcDbLine
    class AcDbPolyline
    class AcDbSpline
    class AcDbCircle
    class AcDbBlockReference
    class AcDbText
    class AcDbDatabase {
        +read(buffer, options, fileType)
        +blockTable / layerTable / textStyleTable
        +events.entityAppended
    }
    class AcDbDatabaseConverterManager {
        +register / unregister / get
    }
    class AcDbDatabaseConverter
    class AcDbNativeDxfConverter
    class AcDbLibreDwgConverter
    class AcGiRenderer {
        +绘制图元接口
    }
    class AcGePoint3d
    class AcGeMatrix3d
    class AcTrBatchedGroup {
        +合批顶点 / 材质
    }
    class AcTrRenderer {
        +WebGL 渲染循环
    }

    AcDbObject <|-- AcDbSymbolTableRecord
    AcDbObject <|-- AcDbEntity
    AcDbSymbolTable <|-- AcDbBlockTableRecord
    AcDbEntity <|-- AcDbCurve
    AcDbCurve <|-- AcDbLine
    AcDbCurve <|-- AcDbPolyline
    AcDbCurve <|-- AcDbSpline
    AcDbCurve <|-- AcDbCircle
    AcDbEntity <|-- AcDbBlockReference
    AcDbEntity <|-- AcDbText
    AcDbDatabase --> AcDbSymbolTable : 持有各符号表
    AcDbDatabase --> AcDbDatabaseConverterManager : read 时获取转换器
    AcDbDatabaseConverterManager --> AcDbDatabaseConverter
    AcDbDatabaseConverter <|-- AcDbNativeDxfConverter
    AcDbDatabaseConverter <|-- AcDbLibreDwgConverter
    AcDbEntity ..> AcGiRenderer : worldDraw
    AcGiRenderer ..> AcTrBatchedGroup : 输出批次几何
    AcTrBatchedGroup ..> AcTrRenderer : 渲染
```

**要点**

- 包职责:`@mlightcad/data-model`(AcDb 数据库与实体)、
  `@mlightcad/geometry-engine`(AcGe 数学与几何)、
  `@mlightcad/graphic-interface`(AcGi 绘制接口)、
  `@mlightcad/three-renderer`(AcTr 合批与 WebGL 渲染)。
