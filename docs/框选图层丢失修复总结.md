# 框选导致图层渲染丢失 — 真实根因分析与修复总结

- 日期：2026-08-18（第二次修正）
- 涉及仓库：`cad-viewer`（three-renderer）
- 关联文档：`docs/大坐标原点平移修复总结.md`、`docs/性能优化总结.md`
- 目标图纸：`F:\gis\CAD\cad\cad\dxf\JKYHMKA01A01yh3m.dxf`（95MB，389,328 实体）

## 1. 结论（本版更正了上一版的分析）

上一版总结把"框选后图层丢失"归因于大坐标 float32 精度残留（跨幅实体量化、深度缓冲、shader 编译真机风险）。本次用真实图纸数据 + 可复现实验逐一证伪，并找到了真正的根因：

**框选本身确实不碰图层可见性、不重建几何。但框选触发的高亮补丁路径存在两个真 bug，会导致渲染器在下一帧抛异常 / shader 编译失败，使整批（整层）内容停止绘制——这才是"图层丢失"的直接原因。**

## 2. 证伪过程（数据与实验）

1. **真实图纸实体摸底**（`realdwg-web/tools/bench/count-entities.cjs`）：LINE 362,128、ARC 17,047、TEXT 8,932、HATCH 860、CIRCLE 353、POINT 5、SPLINE 3。图纸自身跨度仅约 5,320×4,478 单位（坐标量级 39.4M），**最大单实体跨度 10,031 单位**——远小于 1e6 的拆分阈值，跨幅实体理论在本图不成立；每实体中心 rebase 后 float32 ulp ≈ 0.0005，精度完全够用。
2. **Z 范围 [-82,664.7, 9,999]**（岩巷/邻边矿两条带 Z 的 LINE）：正交相机深度分辨率 ≈ 0.0056 单位，深度问题排除。
3. **本机无头 Chrome 即走真实驱动**：`WEBGL_debug_renderer_info` 显示 ANGLE (NVIDIA GeForce GTX 1650 D3D11)——此前的"SwiftShader 通过、真机才失败"假设不成立。
4. **合成夹具测不出问题的原因**：合成夹具全是细线（LineBasicMaterial），不经过 `LineMaterial`/`LineSegments2` 路径；且此前真实图纸复现中渐进转换未完成，框选从未真正执行过（`selectionCount` 恒为 0）。

## 3. 真实根因（两个相互独立的 bug，都在高亮补丁路径）

### 3.1 `installBatchHighlightRenderer` 裸调用前一个 `onBeforeRender`（导致整帧渲染崩溃）

`AcTrBatchHighlightShaders.ts` 包装 drawable 的 `onBeforeRender` 时：

```ts
previousOnBeforeRender?.(renderer, scene, camera, geometry, material, group) // this = undefined
```

宽线批次容器是 `LineSegments2`，其原型上的内置钩子读取 `this.material.uniforms`（刷新 `LineMaterial.resolution`）。裸调用使 `this` 为 undefined，**首次带高亮渲染即抛 `TypeError: Cannot read properties of undefined (reading 'material')`**。异常发生在 `WebGLRenderer.render` 内部 → 整帧渲染中断、动画循环每帧重抛 → 画面冻结/丢失。

复现证据（修复前探针输出）：框选 2200 实体后下一次 `renderer.render()` 直接抛上述 TypeError。

### 3.2 赋值替换注入缺函数定义（导致 LineMaterial shader 编译失败）

上一轮"防御式改进"新增的"赋值替换优先"路径有一个疏漏：当片元源码里存在字面量 `gl_FragColor = vec4(...)` 时，只做了替换，**没有前置注入 `applyBatchHighlight` 的函数定义与 uniform 声明**（`HIGHLIGHT_FRAGMENT_DECL`）。

`LineMaterial`（three 0.172）的原始片元源码恰好包含字面量 `gl_FragColor = vec4( diffuseColor.rgb, alpha );` → 命中赋值替换 → 生成"有调用无定义"的 shader → 编译失败：

```
THREE.WebGLProgram: Shader Error … Material Type: LineMaterial
'applyBatchHighlight' : no matching overloaded function found
```

编译失败的程序不再绘制该材质对应的所有批次——**所有带线宽/LineMaterial 的线批次（整层）消失**。

## 4. 修复

`packages/three-renderer/src/batch/highlight/AcTrBatchHighlightShaders.ts`：

1. `installBatchHighlightRenderer`：以 `previousOnBeforeRender?.call(object, ...)` 调用，保证内置钩子的 `this` 绑定到 drawable 本体。
2. `injectFragmentHighlight`：在赋值替换与 include 插入两条路径之前统一确保 `HIGHLIGHT_FRAGMENT_DECL` 存在，杜绝"有调用无定义"的补丁输出。

新增回归单测 `packages/three-renderer/__tests__/AcTrBatchHighlightShaders.spec.ts`（4 例）：

- 前一个 `onBeforeRender` 以 drawable 为 `this` 被调用、`resolution` uniform 正常刷新、不抛异常；
- 无高亮时仍链式调用前一个钩子；
- 字面量赋值替换后片元同时含定义与调用（version 递增）；
- 无法接线的材质保持原样不半补丁。

## 6. 遗留与说明

1. **上一版修复仍有效**：大坐标原点平移与跨幅实体拆分解决的是"缩放精度"问题（对 39.5M 跨幅实体的图纸仍必要），只是与本图"框选丢图层"无因果关联，予以保留。
2. **`showLineWeight` 与 LineMaterial 路径**：修复覆盖所有 `LineMaterial`/`LineSegments2` 高亮场景（含线宽显示、pattern 线型）。真机上建议再做一次人工确认：打开 JKY 图纸 → 框选 → 高亮着色正常、无控制台错误、缩放/清除后画面完整。
3. 若未来出现其他自定义 `ShaderMaterial` 字面量赋值匹配失败（注入失败仅跳过着色、不影响绘制），防御路径（不补丁不重编译）已兜底。
