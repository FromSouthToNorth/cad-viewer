# 大坐标图层丢失修复（构建期原点平移）总结

- 日期：2026-08-18
- 涉及仓库：`cad-viewer`（three-renderer / cad-simple-viewer / cad-svg-plugin）、`realdwg-web`（data-model / graphic-interface）
- 目标图纸：`F:\gis\CAD\cad\data\JKYHMKA01A01yh3m.dxf`（95MB，389,328 实体；未归零高斯投影坐标，X/Y 最大 3.965e7，Z 最大 1.973e7，float32 在该量级 ulp = 4 单位）
- 关联文档：总体优化历史见 `docs/性能优化总结.md`（本次内容同步为其 6.5 节）

## 1. 背景与现象

滚动缩放时渲染图层"丢失"。此前已完成的 M0-M2（本地链接与基准、解析零分配、渐进渲染、加载进度 UI、16% 卡死 HANDSEED BigInt 修复）解决了打开阶段的卡顿，但大坐标导致的渲染精度问题仍未处理。用户判断与坐标范围有关——**已证实**。

## 2. 诊断与关键更正

深入渲染器代码后，对早期诊断有一处重要更正：

- **早期结论"100% 实体因 1e6 阈值走 unbatch"有误。** `AcTrRenderContext` 的默认策略是 `alwaysBatchDrawPolicy`（`AcTrRenderContext.ts:41`），带 1e6 阈值的 `defaultBatchDrawPolicy` 并未在生产路径启用。实际运行中实体正常合批。
- **批容器本身已经精确**：顶点在写入 float32 前按批原点 rebase（`rebaseGeometryInPlace`），容器 `position` 存 JS 双精度世界偏移。
- **相机矩阵链安全**：THREE.js 在 JS 双精度中计算 `modelViewMatrix`（相机与物体的千万级平移相乘时相消，结果值本身很小），无需场景级/相机级平移。
- 所有批次与 unbatched 克隆均 `frustumCulled = false`，排除视锥剔除因素。

真正把大坐标"烧进" float32 的只有以下 5 处，即本次修复对象：

| # | 位置 | 问题 |
| --- | --- | --- |
| 1 | `AcTrPolygon`（图案/实心填充，宽多段线 `renderer.area()` 也走这里） | `THREE.ShapeGeometry` 直接用 WCS 点三角化，顶点以 float32 存绝对世界坐标（ulp=4） |
| 2 | `AcTrImage` | 同上 |
| 3 | data-model `AcDbFace` / `AcDb3dSolid`（含 ACIS 线框链） | `new Float32Array(世界坐标)` 打包线段，量化发生在任何 rebase 之前，无法恢复（`AcDbTable` 经核实是表内局部坐标，无需改） |
| 4 | `buildAreaGeometry`（直接批路径） | 先取量化后的 bbox 再 rebase（先量化后减原点），且未计入 `mesh.position` |
| 5 | `AcTrBaseView.createCamera` | near/far 固定 0.1/1000、相机 z=500，仅覆盖约 1500 单位世界 Z 带；本图 Z 高达 19.7M 的实体被裁剪永远不可见（与缩放无关的独立问题） |

放大到细节尺度时，量化把填充边界/短线段塌缩到 4 单位网格上，三角形退化、填充消失——即"图层丢失"现象。

## 3. 修复方案：构建期原点平移

原则：**不动场景图与相机**，把"归零"前移到所有写入 float32 的点上——在双精度下完成平移，再进 float32；世界定位放回 `Object3D.position`（JS double）。

### 3.1 cad-viewer 改动清单

| 文件 | 改动 |
| --- | --- |
| `packages/three-renderer/src/object/AcTrPolygon.ts` | 构造时用 WCS 双精度边界点求 bbox 中心作锚点；创建 `THREE.Shape`/`Path` 时点先平移 `-anchor` 再三角化（孔洞合并/PolyBool 拓扑仍用原始 WCS 点，不改变 epsilon 行为）；`mesh.position = anchor`；`wcsBbox = 局部bbox + anchor`；渐变属性用局部 bbox 归一化，语义不变 |
| `packages/three-renderer/src/object/AcTrImage.ts` | 同上：boundary 先减中心再 `ShapeGeometry`，`mesh.position = 中心`，`wcsBbox` 补回平移 |
| `packages/three-renderer/src/object/AcTrLineGeometryBuilder.ts` | `buildAreaGeometry`：计入 `mesh.position` 得到真实 WCS bbox 与 `worldOffset`，rebase 只减残差 `worldOffset - meshPosition`（避免对已局部化的几何二次放大）；`buildLineSegmentsGeometry` 输入放宽为 `Float32Array \| Float64Array` |
| `packages/three-renderer/src/object/AcTrLineSegments.ts` | 输入类型放宽；rebase 读路径兼容 Float64，localOrigin 双精度计算 |
| `packages/three-renderer/src/renderer/AcTrRenderer.ts` | `lineSegments` 与 `AcTrDirectCapturePayload.array` 类型放宽 |
| `packages/three-renderer/src/viewport/AcTrCamera.ts` | 新增 `near`/`far` 访问器 |
| `packages/three-renderer/src/viewport/AcTrBaseView.ts` | 新增 `updateCameraDepthRange(zMin, zMax)`：内容高于相机时抬升相机（z = zMax + 1000），near/far 覆盖整段 Z 范围 |
| `packages/cad-simple-viewer/src/view/AcTrView2d.ts` | `zoomTo` 与渐进 fit 后调用 `updateCameraDepthRangeFromScene()`（用 `scene.box` 的 Z 范围） |
| `packages/cad-svg-plugin/src/AcSvgRenderer.ts`、`AcSvgLineSegments.ts` | `lineSegments` 类型同步放宽 |

## 5. 注意事项与遗留

1. **Z 深度取舍**：near/far 覆盖 19.7M 量程后，24 位深度缓冲分辨率约 1.2 单位；Z 相邻 <1.2 单位的不同实体理论上可能 z-fight。若真机出现叠层闪烁，回退方案是对 2D 视图做 Z 压平，届时单独评估。
2. **npm 发布**：上游 data-model/graphic-interface 改动需发布新版本后才会对在线引用 npm 包的 cad-viewer 生效；期间保持本地链接（`node tools/use-local-realdwg.mjs --on`，`pnpm-workspace.yaml` overrides 勿回退）。
3. **未采用的方案**：场景级/相机级 RTE 平移（每帧相对眼重定基）经评估不必要——矩阵链在 JS 双精度下安全，且改动面大（拾取临时对象、bbox 合并、预览克隆、CSS2D 全部要配合补偿），回归风险高。
4. 早期文档中"100% unbatch"的旧结论已在 `docs/性能优化总结.md` 第 6 节与第 7 节更正。
